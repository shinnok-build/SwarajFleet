# Browser simulation tests

Headless (Node, no browser needed) tests for the engine embedded in
`site/index.html`. Run them all with `make site-test`, or individually:

```bash
node tests/site/engine.test.js   # invariants: 0 collisions, completion, determinism
node tests/site/crosscheck.js    # JS engine vs Python reference, 72 identical worlds
node tests/site/dom_smoke.js     # boots the page with a fake DOM, exercises all controls
node tests/site/dom_run.js       # plays the default world to completion through the UI loop
```

## Fixtures

`fixtures/python_worlds.json` + `fixtures/python_results.json` are the raw
output of the Python reference protocol, used by `crosscheck.js` to prove the
browser engine is a faithful port:

- `fixtures/python_worlds.json` — 72 world specs (layouts A/B/C × fleets 5/10 × 12 seeds), generated by `proto/gen_worlds.py`.
- `fixtures/python_results.json` — the Python protocol's own results on those exact worlds, produced by `proto/run_worlds.py`.

Regenerate both (requires Python 3.10+):

```bash
python3 proto/gen_worlds.py && python3 proto/run_worlds.py
cp proto/python_worlds.json proto/python_results.json tests/site/fixtures/
```

## Documented residual livelock

The protocol has a rare residual livelock (the locked benchmark reports 2/90
at 5 robots). `engine.test.js` encodes the known-affected worlds
(`KNOWN_LIVELOCKED`) for the browser seed space; every one of them was
independently verified to livelock in the Python reference as well, so the
exception is a property of the protocol/world — not of the port.
